# 004: Seed labels from a classified GeoTIFF or a model

**Goal:** Fill spec 003's label store on the open imagery, never on imagery nodata, from a classified GeoTIFF or from a model run on that imagery, merged with or replacing existing labels, so the user corrects it with the brush, exports it as a label GeoTIFF that imports back unchanged, and retrains.

**Status:** Approved (Gage, 2026-10-26). Build order: after spec 003, before spec 005 (AlphaEarth training), which uses these labels unchanged. **ADRs:** 0013 label GeoTIFF format (Accepted), which amends 0001 and fills 0010's open save format; uses 0002. External model files and GPU inference are covered by ADR 0012 (Accepted) and spec 006 (localhost GPU server).

**Decided (Gage, 2026-10-26):**
- Seed from a classified GeoTIFF and from our model JSON. External model files are out (ADR 0012). Outputs are a label GeoTIFF export and retraining. Number 004, built right after 003.
- The user chooses Merge or Replace when seeding.
- Classifiers never output nodata. The input imagery's nodata masks seeded labels.
- Imagery-nodata pixels are never labelled, by any path: seeding masks them and spec 003's brush (amended) skips them, so export and import round-trip exactly.
- Approved defaults: the 256-tile cap stays in v1 (an OPFS store or view-only seeding can follow); Min. confidence defaults to 0; class rasters are Uint8 only; spec 001's classification export doesn't write the class table; a localhost GPU server becomes spec 006, after this one, and change detection and prediction move to 007 and 008; Merge is the default mode; a class file's GDAL_NODATA is honoured; the mask uses all imagery bands.

## Scope
In: "Import labels" (a classified GeoTIFF plus an optional class-map JSON), resampled onto the imagery grid; "Seed from model" with a "Min. confidence" field; a Merge/Replace choice; masking by imagery nodata; editing seeds with spec 003's brush; "Export labels" as a GeoTIFF on the imagery grid that imports back to the same labels and classes; Train as in spec 003.
Out: external model files, ONNX and GPU inference (ADR 0012, spec 006); multi-band, 16-bit or float class rasters; CRSs outside ADR 0002; majority or other resampling; matching classes other than by exact name; seeding or labelling AlphaEarth; `.aux.xml` sidecars, RATs and QGIS styles; a TIFF colour map in the export; raising `MAX_LABEL_TILES`; undo.

## Interfaces (`core/`)
```ts
const CLASS_ITEM = "GEOAPP_CLASSES"; // GDAL_METADATA dataset item (ADR 0013)
type ClassEntry = { value: number; name: string; colour?: string }; // value: source pixel value 0..255; colour "#rrggbb"
seedWindows(dst: Grid, src: Grid): Window[] // dst tileWindows with a pixel centre on src; row-major; may over-include, never misses
sourceCells(dst: Grid, src: Grid, w: Window): Int32Array // per pixel of w, row-major: col, row of the src pixel holding its centre, or -1, -1
gatherCells(cells: Int32Array, sw: Window, data: Uint8Array, out: Int16Array): void // out[i] = data at cell i when inside src window sw; else untouched (caller fills -1)
markValues(vals: Int16Array, seen: Uint8Array): void            // seen (256 entries)[v] = 1 for every v >= 0
classesFromValues(seen: Uint8Array, nodata: number | null): ClassEntry[] // ascending values, nodata skipped, name "Class v"
parseClasses(json: unknown, nodata: number | null): ClassEntry[] // throws Error naming the bad field
mergeClasses(list: LabelClass[], incoming: { name: string; colour?: string }[]): { list: LabelClass[]; values: number[] } | "too many"
  // list, then incoming names not in it (exact match), appended in order; values[i] = label value of incoming[i]; missing colours from the palette by final position; > 255 -> "too many"
seedLut(entries: ClassEntry[], values: number[]): Uint8Array    // 256 entries: entries[i].value -> values[i]; unlisted -> 0
applyLut(vals: Int16Array, lut: Uint8Array): Uint8Array         // -1 -> 0
maskNodata(tile: Tile, labels: Uint8Array): void                // labels[i] = 0 where any band equals tile.nodata or is NaN
seedFromModel(model: Model, tile: Tile, minProb: number, values: number[]): Uint8Array // values[argmax] where max softmax >= minProb, else 0; nodata -> 0
mergeTile(old: Uint8Array | undefined, seed: Uint8Array): Uint8Array // old where old > 0, else seed
putTile(store: LabelStore, w: Window, labels: Uint8Array): "ok" | "full" // replaces w's tile; all-zero deletes it; "full" changes nothing
encodeClasses(classes: LabelClass[]): string // `<GDALMetadata><Item name="GEOAPP_CLASSES">` + XML-escaped JSON ClassEntry[] (value = index + 1)
decodeClasses(inner: string): unknown       // unescapes &amp; &lt; &gt; &quot; &apos;, then JSON.parse; throws on bad JSON
```
**Rules.**
- **Import labels.** Enabled while local imagery is open. The user picks a GeoTIFF and, optionally, a class-map JSON (a `ClassEntry[]`). A file that isn't single-band with 8-bit unsigned samples is refused with "Label files must be single-band 8-bit GeoTIFFs." (this also refuses AlphaEarth files). Its CRS and extent must pass spec 001's checks for opening a raster, with the same messages. `nodata` is the file's GDAL_NODATA when that is an integer from 0 to 255, else null. A tag is honoured because spec 001's classification export writes 255 at imagery nodata; an untagged file reads every value as a class.
- **Classes.** The table comes from the class-map JSON if one is given, else the file's `CLASS_ITEM` (`decodeClasses` of geotiff.js `getGDALMetadata()[CLASS_ITEM]`), else `classesFromValues` of the values at the sampled cells, collected in a first pass. Tables pass through `parseClasses`, which applies spec 003's name rule and rejects 0 or more than 255 entries, duplicate values and the nodata value. On error ui shows "The class table is invalid: <field>." Each colour comes from the entry, else from spec 003's palette by position (`mergeClasses`). Nodata values, unlisted values and pixels whose centre is off the file stay unlabelled. Names are edited afterwards in spec 003's list; there's no prompt.
- **Resampling.** Nearest pixel centre: imagery pixel (c, r)'s centre (c + 0.5, r + 0.5) goes through the imagery's gt, `core/crs` and the inverse of the file's gt, and is floored. This is spec 005's transfer at k = 1.
- **Nodata.** In both paths `maskNodata` clears every seeded pixel where any imagery band equals the imagery's GDAL_NODATA or is NaN: spec 001's rule over all bands, which spec 003's training and brush use. The brush skips those pixels too, so no stored label is ever on imagery nodata.
- **Tiling.** Import visits each window of `seedWindows(imagery, file)` once per pass (two passes when classes come from values; the first reads no imagery). `io/` reads, one at a time, only the file's 256x256 windows, aligned to the file's own grid, that hold one of that window's cells, then the imagery window once if any gathered label is non-zero. At most one file or imagery window is held at a time, besides the label stores.
- **Seed from model.** Enabled while local imagery is open and a model exists: trained, or loaded and validated as in spec 001 against the imagery's band count (spec 005 later adds the "imagery" source check). "Min. confidence" is a number field from 0 to 1, step 0.05, default 0. A value outside 0..1 disables the button and shows "Min. confidence must be between 0 and 1." Seeding reads every imagery window once and applies `seedFromModel` (`predictTile`'s logits and argmax, first maximum), then `maskNodata`. The incoming classes are `model.classes`, without colours.
- **Merge or Replace.** While any pixel is labelled, a "Seed mode" select offers Merge (the default, since it can't destroy work) and Replace; otherwise it is disabled and seeding replaces with no confirm. Merge fills only unlabelled pixels, so painted labels win, and the list is `mergeClasses(list, incoming)`. Replace first asks `confirm("Replace labels?")`, where Cancel changes nothing, and uses `mergeClasses([], incoming)`. Both build a new store (Merge: a shallow copy of the current one) and list, `putTile` each window's `mergeTile` of the new store's tile and the non-zero seed, and swap them in only on success. While seeding runs, the brush, Train, Import labels, Seed and Export labels are disabled, and while spec 003's paint queue is non-empty, Import labels and Seed are. Then nothing changes and ui shows: on `"full"`, "Label limit reached (256 tiles of 256 x 256 px). Nothing was seeded."; on `"too many"`, "Too many classes (max 255). Nothing was seeded."; when N = 0, "No labels to seed here." On success: "Seeded N pixels in K classes.", N being the pixels the seed labelled (in Merge, only previously unlabelled ones) and K their classes.
- **Edit and retrain.** Seeded labels are ordinary spec 003 labels. The brush paints and erases them, Train trains on them, and spec 005 transfers them, all unchanged.
- **Export labels.** Enabled while local imagery is open. ADR 0001's writer writes the imagery's whole grid: tags copied from the imagery, 256x256 tiles (each the stored tile, or zeros), GDAL_NODATA "0", and GDAL_METADATA `encodeClasses(list)` listing every class, used or not. Value 255 (the 255th class) is therefore a class, not nodata. Spec 001's classification export is unchanged: classes 0..254, GDAL_NODATA "255". Export reads no imagery window, and spec 001's size limit applies.
- **Saving labels.** Export labels and Import labels (with Replace) take the place of spec 003's deferred save and load. An exported file imports back to the same store and class list. Between the two steps, labels still live only in memory.
- **Test data.** Small class rasters (under 100 KB) over spec 001's EPSG:4326 fixture, in EPSG:32633: values 0, 3, 7 and 255 with GDAL_NODATA 255; the same without GDAL_NODATA; one with `CLASS_ITEM`; a class map; and 3-band and 16-bit files for the refusals. Larger rasters, and imagery with GDAL_NODATA (a block nodata only in band 2) or a Float32 band with NaN, are generated in memory by tests.

## Acceptance criteria
1. `sourceCells`: on equal grids, every pixel maps to itself. With an EPSG:4326 dst and an EPSG:32633 src, the points in `tests/fixtures/crs-points.json` give the floor of their recorded src coordinates, skipping points within 0.01 px of an edge. Pixels off src give -1, -1.
2. `seedWindows`: checked by brute force over every window of a 3x3-window dst, it holds each window with a cell on a src in another CRS. A disjoint src gives [].
3. `parseClasses` accepts a valid table. It rejects each of the following, naming the field: a non-array; 0 or 256 entries; a value that isn't an integer, is outside 0..255, is duplicated or equals nodata; a name that is empty, duplicated or not a string; a colour that isn't "#rrggbb".
4. With values {0, 3, 7} present and nodata 255, `classesFromValues` gives "Class 0", "Class 3", "Class 7". `seedLut` with values [1, 2, 3] maps 0 -> 1, 3 -> 2, 7 -> 3, and with [5, 1, 9] maps 0 -> 5, 3 -> 1, 7 -> 9; everything else maps to 0. `applyLut` maps -1 to 0.
5. `seedFromModel` on spec 001 criterion 7's tile and model with values 1..n: at minProb 0 it equals `predictTile` + 1, with 255 -> 0. With values reversed, each pixel gets values[`predictTile`]. At minProb 0.9, pixels whose max softmax is below 0.9 are 0 and all others keep their minProb 0 value.
6. `mergeClasses`: with [] it returns the incoming names, values 1..n and palette colours by position where none is given. List [A, B] with incoming [B, C] gives [A, B, C], A and B keeping their colours, and values [2, 3]. 254 classes plus 2 new names gives `"too many"`. `mergeTile` keeps every non-zero old pixel and takes the seed elsewhere; undefined old gives the seed.
7. `maskNodata`: a pixel equal to `tile.nodata` in band 2 only becomes 0, as does a NaN pixel in a Float32 band. With nodata null only NaN is masked. Other pixels are unchanged.
8. `putTile` replaces a tile, deletes it when given all zeros, and at `MAX_LABEL_TILES` returns `"full"` for a new key (store unchanged) but still replaces an existing key.
9. `encodeClasses` then `decodeClasses` round-trips names containing `<`, `>`, `&`, `"`, `'` and non-ASCII text. On a written file, geotiff.js `getGDALMetadata()` returns exactly one dataset item named `GEOAPP_CLASSES`.
10. Export (EPSG:4326 fixture): geotiff.js reads back the imagery's width, height, origin, resolution and GeoKeys, with 256x256 tiles and GDAL_NODATA "0". Pixels equal the store, and 0 where no tile is stored. With 255 classes, a pixel of class 255 reads back as 255 and imports as class 255. Export reads no imagery window (instrumented source).
11. Round trip (e2e, imagery generated with a nodata block in band 2, strokes crossing it): paint three classes, rename one to `Mangrove & <salt>`, recolour one and add an unused class. Export, open the imagery again and accept spec 003's discard confirm (the store is now empty), then import the export. Every tile is byte-equal per key, no stored pixel is imagery nodata, and the class list (names, colours, order, including the unused class) is identical.
12. Classes (e2e): the `CLASS_ITEM` file takes its names and colours from the item. The same file with a class map takes the map's names, and its unlisted values stay unlabelled. The 0/3/7 file gives "Class 0", "Class 3", "Class 7"; without GDAL_NODATA, 255 becomes a class too. An invalid class map shows the message and changes nothing.
13. Resampling and mask (io, brute force, fixtures and generated nodata imagery): each imported pixel is 0 where any imagery band is nodata or NaN, else `seedLut` of the file value at `sourceCells` of that pixel. Model seeding gives 0 at those pixels too. After brush strokes across a nodata block (e2e), then a Merge import and a Merge model seed, every imagery-nodata pixel is still unlabelled.
14. Reads (instrumented file and imagery sources): an import's values pass reads no imagery window, and its labelling pass reads exactly the imagery windows whose gathered labels are non-zero, once each. Every file read is a 256x256-aligned window of at most 256x256 that holds a cell of the current imagery window, read at most once per imagery window per pass. Model seeding reads each imagery window exactly once.
15. Refusals (e2e): the 3-band file, the 16-bit file and a spec 002 fixture (a) AlphaEarth COG show "Label files must be single-band 8-bit GeoTIFFs.", and an unsupported CRS shows spec 001's message. A file that doesn't overlap the imagery shows "No labels to seed here." Nothing changes in any of these cases.
16. Merge, Replace and cap (e2e unless noted): with no labels, Seed mode is disabled and an import shows no confirm. With labels painted it is enabled with Merge selected. A Merge import shows no confirm, keeps every painted pixel's class, labels only unlabelled pixels, and appends only new names. Replace shows the confirm: Cancel keeps labels and classes, OK replaces them. While an import runs (paused file source), the brush and Train are disabled, and while a stroke's mask reads are pending (paused imagery source), Import labels and Seed are. A Merge passing 255 classes shows its message and changes nothing. Seeding a 4352x4352 class raster generated in memory onto an equal grid (io) stops with `"full"` in both modes and leaves the store and list unchanged, and ui maps `"full"` and `"too many"` to their messages (unit).
17. Seed from model (e2e, EPSG:4326 fixture): Seed is disabled until a model exists. After training on two painted classes, a Replace seed at 0 gives tiles equal to `seedFromModel` then `maskNodata` on every window, and the list equals `model.classes`. A Merge seed keeps the painted pixels and leaves the list unchanged. At 0.9 only pixels whose max softmax is at least 0.9 are labelled. A value of 1.5 shows the message and disables Seed.
18. Edit and retrain (e2e): after an import, a right drag clears the selected class in a seeded area, and a left drag paints. Train then meets spec 003 criterion 15 (N = labelled pixels, `model.classes` = list).
19. Privacy (request log): importing, seeding and exporting labels make no network requests.
