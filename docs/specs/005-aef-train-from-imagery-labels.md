# 005: Train on AlphaEarth from imagery labels

**Goal:** Transfer brush labels painted on local imagery onto an AlphaEarth AOI, train spec 001's logistic regression on the 64 embedding bands, and classify and export the AOI on the AlphaEarth grid.

**Status:** Approved (Gage, 2026-10-26). Needs spec 002 (AlphaEarth source) and spec 003 (brush labels), and is built after spec 004 (label seeding). **ADRs:** 0011 drawn AOI + supersampled majority transfer (Accepted); uses 0001, 0002, 0005 and 0010.

**Decided (Gage, 2026-10-26):**
- AlphaEarth is never hand-labelled; embeddings are only trained on. Labels on local imagery can train a model on AlphaEarth if the user wants.
- The AOI is the drawn rectangle (or a local AlphaEarth file's grid).
- Transfer is by majority over labelled sub-points; ties leave the pixel unlabelled (ADR 0011). `K_MAX` stays 8.
- Models carry optional tags (`meta`) now; validation uses them when present.
- The user picks the year, with no check against the imagery's date.
- A loaded model can classify and export AlphaEarth with no imagery open; training still needs imagery labels. The `meta.aef.aoi` tag stays as specified, with no ADR for the tag format.
- An untagged model (no `meta`) is accepted on AlphaEarth only if it uses bands 1..64, each once; any other band set is refused there. Tagged models follow the source rule; untagged models on imagery stay as in spec 001.

## Scope
In: a "Train on" choice between "Imagery bands" (spec 003, the default) and "AlphaEarth <year>"; label transfer; training; classifying the whole AOI; GeoTIFF export on the AOI grid; model tags; save/load model as in spec 001; classifying and exporting the AOI with a loaded model and no imagery open.
Out: an AOI taken from the imagery's extent or from the labels; models combining imagery bands with embeddings; several years or AOIs in one model; a year-mismatch warning; training with no imagery open; showing transferred labels or results on the map; transferring labels back to the imagery.

## Interfaces (`core/`)
```ts
const K_MAX = 8;
subsamples(src: Grid, aoi: Aoi): number // k = clamp(ceil(AEF_RES / s), 1, K_MAX); s = shorter side (m) of the src pixel at the AOI centre, projected to aoi.epsg
transferWindows(store: LabelStore, src: Grid, aoi: Aoi): Window[] // AOI tileWindows that can receive a label, row-major; may over-include, never misses
transferLabels(store: LabelStore, src: Grid, aoi: Aoi, w: Window, k: number): Uint8Array // labels for AOI window w, row-major; 0 = unlabelled
type ModelSource = "imagery" | "aef";
type ModelMeta = { source: ModelSource;           // the only required field
  created?: string; app?: string;                 // ISO 8601 UTC (toISOString); package.json version
  bandNames?: string[];                           // one per model.bands entry
  epsg?: number; pixelSize?: [number, number];    // training grid CRS; pixel width, height in CRS units
  colours?: string[]; counts?: number[];          // per class: "#rrggbb"; training samples
  aef?: { year: number; aoi: Aoi; transfer: { rule: "majority"; k: number } } }; // source "aef" only
type Model = SpecOneModel & { meta?: ModelMeta }; // spec 001's Model; version stays 1
classCounts(y: Uint8Array, classes: number): number[]
validate(model: unknown, bandCount: number, source?: ModelSource): asserts model is Model // extends spec 001's; no meta + "aef" needs bands 1..64
```
`Grid`, `LabelStore` and `labelSamples` come from spec 003, and `Aoi` comes from spec 002 (it has `Grid`'s shape).

**Rules.**
- **Label source.** Transfer reads spec 003's label store, whatever filled it. Labels painted with the brush, labels seeded by spec 004 from a classified GeoTIFF or a model, and labels imported from a spec 004 label export all work unchanged.
- **AOI.** The AOI is spec 002's drawn rectangle, or a local AlphaEarth file's grid. It is never the imagery's extent or the labels' bounding box, so requests depend only on what the user drew and the year (ADR 0005, 0011). Labels outside the AOI are ignored.
- **Transfer.** For AOI pixel (c, r), the sub-points are (c + (i+0.5)/k, r + (j+0.5)/k) for i, j in 0..k-1. Each goes through `aoi.gt` to UTM, then to lon/lat (`core/crs`), then through `pixelAt(src)`. A sub-point's label is the store value there, or 0 when it falls off the raster. If fewer than ceil(k²/2) sub-points are labelled, the pixel gets 0. Otherwise it gets the class with the most labelled sub-points, or 0 if two or more classes tie for most. At k = 1 this is the nearest-neighbour label at the pixel centre. Transfer reads only the label store, never an imagery window.
- **Training on AlphaEarth.** The "AlphaEarth <year>" option is enabled once AlphaEarth data is loaded (spec 002) while local imagery is open. With no imagery open, Train stays disabled. Training reads each window of `transferWindows` once from the cache, computes `transferLabels` with k = `subsamples(src, aoi)`, applies `labelSamples` on bands 1..64, and fits every class in the list. It needs at least two classes with transferred samples, otherwise ui shows "Fewer than two classes have labels inside the AlphaEarth area." On success, ui shows "Trained on N AlphaEarth pixels."
- **Model tags.** Both training paths (spec 003 and this one) fill every `meta` field that applies (`aef` only for AlphaEarth). `bandNames`: "A00".."A63" for AlphaEarth; for imagery, each band's GDAL `DESCRIPTION` (geotiff.js 3.0.5 `getGDALMetadata(band - 1)`, checked 2026-10-26), else "Band N". `epsg` and `pixelSize` describe the training grid. `counts` is `classCounts(y, classes.length)`. `meta` never holds a file name or path, the imagery's geotransform or extent, or label geometry; `aef.aoi` is the drawn area, which the requests already reveal.
- **Validation.** Without `meta`, `validate` behaves as in spec 001, so old models load, except that for source "aef" it then also requires `bands.length` 64 (with spec 001's range and duplicate checks, that means bands 1..64, each once, in any order); otherwise ui shows "This model has no source tag and doesn't use all 64 AlphaEarth bands, so it can't classify AlphaEarth." With `meta`, `source` must be "imagery" or "aef" and equal the `source` argument when given, checked before spec 001's checks; `bandNames`, `colours` and `counts`, when present, must match `bands.length`, `classes.length` and `classes.length`. Unknown `meta` keys are ignored. On a source mismatch ui shows "This model was trained on AlphaEarth embeddings, not imagery bands." or the reverse.
- **Classify and export.** Both follow the "Train on" choice. For AlphaEarth, `predictTile` runs on every AOI window of the cache (or local file), and ADR 0001's writer writes the result on the AOI grid. There is no input TIFF to copy tags from, so `io/` builds them from `aoi`: GTModelType projected, GTRasterType PixelIsArea, ProjectedCSTypeGeoKey `aoi.epsg`, ModelPixelScale 10, ModelTiepoint at the `gt` origin. For "Imagery bands", specs 001/003 apply unchanged. "Load model" validates against the chosen source and its band count. With no imagery open the source is AlphaEarth: once AlphaEarth data is loaded, a model that passes `validate(model, 64, "aef")` (`meta.source` "aef", or no `meta` and bands 1..64) enables Classify and Export on the AOI grid as above.
- **Test data.** `make_aef_fixtures.py` also writes (e) `imagery.tif`, staying inside the 5 MB budget: a 3-band Uint8 EPSG:32617 GeoTIFF at 5 m, band descriptions "red", "green", "blue", covering the (a) chip plus a 20 m margin. Its origin is offset 2.5 m in x and y from the 10 m grid, so k = 2 and the grids don't align. Its RGB values are `aefPreview` of the reference chip, nearest neighbour. Cross-CRS transfer is unit-tested on synthetic grids.

## Acceptance criteria
1. `subsamples`: an EPSG:32617 source grid with 10, 30, 3 and 0.5 m pixels gives 1, 1, 4 and 8 for an EPSG:32617 AOI.
2. Identity: when the source grid equals the AOI grid (k = 1), `transferLabels` returns the stored labels unchanged in every window.
3. Rule (2.5 m EPSG:32617 source aligned to the AOI, k = 4; counts of 16 sub-points, rest unlabelled): 8 of class 1 gives 1; 7 gives 0; 15 of 1 + 1 of 2 gives 1; 5 of 1 + 3 of 2 gives 1; 4 of 1 + 4 of 2 gives 0; 6 of 1 + 5 of 2 + 5 of 3 gives 1; 3 of 1 + 3 of 2 + 2 of 3 gives 0.
4. Reprojection (EPSG:4326 source at 4.5e-5° over the (a) chip, AOI EPSG:32617): with a 40x40-pixel block labelled 1, every AOI pixel whose centre lies at least 10 m inside the block's outline (projected to UTM) gets 1, and every one at least 10 m outside gets 0.
5. `transferWindows`: it contains every AOI window where `transferLabels` is non-zero, checked by brute force over all windows of a 2x2-window AOI with labels on a window corner. It returns [] for an empty store and for a store whose tiles all lie outside the AOI.
6. Reads (instrumented cache and imagery source): training on AlphaEarth reads exactly the cached windows in `transferWindows`, once each, and no imagery window. The sample count equals the non-zero transferred pixels that aren't NaN, and the model equals `fit` on those samples.
7. End-to-end (e2e, fixtures (a), (b) and (e)): open (e), paint two classes (by mouse and through `__geoapp.labels`), draw the AOI over the chip, fetch 2021, choose "AlphaEarth 2021", train, classify and export. `model.bands` is 1..64 and `model.classes` is the class list. The output is EPSG:32617 with origin `aoi.gt`, the AOI's width and height, 10 m pixels, 256x256 tiles and GDAL_NODATA "255". Its pixels equal `predictTile` on the cached tiles (255 where embeddings are NaN). This replaces spec 002's original criterion 11.
8. Local file (e2e): with the fixture (a) west-half COG opened as AlphaEarth data, training and export use that COG's north-up grid as the AOI. The output's origin and size equal that grid.
9. Choice and messages (e2e): "AlphaEarth" is disabled until AlphaEarth data is loaded. If only one class has labels inside the AOI, training shows the message and makes no model. With "Imagery bands", spec 003 criterion 15 still passes on (e).
10. Privacy (request log): for one AOI and year, the `AEF_BASE` requests (URL + Range) are identical in a session with no labels and in one with three classes painted, some of them outside the AOI. After the fetch, transfer, training, classification and export make zero requests.
11. Tags (e2e, criterion 7's run plus an "Imagery bands" run on (e) saved as a distinctively named file): the AlphaEarth model's `meta` has source "aef", `bandNames` "A00".."A63", epsg 32617, pixelSize [10, 10], `aef` { year 2021, `aoi` equal to the AOI, transfer { "majority", k 2 } }. The imagery model's has source "imagery", no `aef`, `bandNames` ["red", "green", "blue"] and pixelSize [5, 5]. In both, `colours` equals the class colours, `counts` equals `classCounts` and sums to the sample count, `created` is between the test's start and end, `app` equals package.json `version`, and `meta` has no other keys. Neither saved JSON contains the file name. A raster without GDAL_METADATA gives "Band 1".."Band N".
12. `validate` (unit): an "aef"-tagged 64-band model is refused for "imagery" with bandCount 64, and an "imagery"-tagged 3-band model is refused for "aef", each naming `meta.source`; each is accepted for its own source. An untagged 3-band model is accepted for "imagery" (bandCount 3) and refused for "aef" (bandCount 64) naming `bands`; an untagged model with bands 1..64 is accepted for "aef". A non-object `meta`, a missing or unknown `source`, or a `bandNames`, `colours` or `counts` length mismatch is rejected naming the field. An unknown `meta` key is accepted. Save then load keeps `meta` unchanged, and spec 001 criteria 10-11 still pass.
13. Load model (e2e): with (e) open and AlphaEarth 2021 fetched, loading criterion 7's model under "Imagery bands", or criterion 11's imagery model under "AlphaEarth 2021", shows the matching mismatch message and leaves Classify disabled. Each model classifies under its own source.
14. No imagery (e2e, fixtures (a) and (b), no imagery open): fetch the fixture AOI for 2021, then load criterion 7's saved model. Train stays disabled; Classify and Export are enabled, and the exported output meets criterion 7's grid checks and equals `predictTile` on the cached tiles. The same model with `meta` removed (bands 1..64) is accepted and gives the same output. Criterion 11's imagery model shows "This model was trained on imagery bands, not AlphaEarth embeddings."; with `meta` removed it shows "This model has no source tag and doesn't use all 64 AlphaEarth bands, so it can't classify AlphaEarth." Both leave Classify and Export disabled.
15. Seeded labels (e2e, fixtures (a), (b) and (e); criterion 7's strokes avoid (e)'s nodata pixels, so spec 004's import masks nothing): export criterion 7's painted labels with spec 004's "Export labels", reopen (e), and import that file instead of painting. Training on "AlphaEarth 2021" then gives the same `W`, `b` and `counts` as criterion 7.
