# 003: Paint-brush labels for local imagery

**Goal:** Label a local GeoTIFF by painting classes onto its pixel grid with a resizable brush, and train spec 001's logistic regression on the painted pixels.

**Status:** Draft — awaiting Gage's approval. **ADRs (Proposed):** 0009 brush for local imagery, polygons for AlphaEarth; 0010 sparse label tiles, per-tile overlays, run-length JSON. Built after spec 002. The defaults below are recommendations; the open questions are at the end.

**Decided (Gage, 2026-10-26):** The brush replaces polygon drawing for local imagery. It doesn't apply to AlphaEarth embeddings ("not human readable"), which keep spec 002's polygon labelling.

## Scope
In: a brush with a hover preview; left button paints, right button erases; brush size controls; Paint and Pan modes; a class list (add, rename, recolour, select); labels stored as sparse tiles on the raster grid and shown on the map; training from painted pixels; saving and loading labels as a local file.
Out: AlphaEarth sources (spec 002, unchanged); polygons on local imagery; undo; flood fill; disc or other brush shapes; deleting classes; painting by touch; exporting labels as GeoTIFF; showing the classified result.

## Interfaces (`core/`)
```ts
const BRUSH_SIZES = [1, 3, 7, 15, 31, 63, 127]; // odd, so the square centres on the pointer's pixel; default 7
const MAX_LABEL_TILES = 256;                     // 16 MiB of label tiles (ADR 0010)
type Grid = { width: number; height: number; epsg: number; gt: Affine };
type LabelClass = { name: string; colour: string };  // "#rrggbb"; label value = list index + 1
type LabelStore = { width: number; height: number; tiles: Map<string, Uint8Array> };
  // key `${x0},${y0}` of a tileWindows() window; row-major, window-sized; 0 = unlabeled; no all-zero tile is kept
pixelAt(grid: Grid, lon: number, lat: number): [number, number]  // [col,row] containing the point (floor); normalizeLon first; may be off-raster
footprint(dims: Pick<Grid, "width" | "height">, col: number, row: number, side: number): Window | null // col±(side-1)/2, row±(side-1)/2, clipped; null if empty; Window from core/grid
footprintRing(grid: Grid, w: Window): [number, number][]          // lon/lat TL, TR, BR, BL, TL of w's outer pixel edges (toLonLat)
strokeCells(a: [number, number], b: [number, number]): [number, number][] // 8-connected Bresenham, both ends included
brush(store: LabelStore, w: Window, value: number, erase: boolean): "ok" | "full" // paint: set w to value; erase: clear pixels equal to value
labelWindows(store: LabelStore): Window[]                           // windows of stored tiles, row-major
labelSamples(tile: Tile, labels: Uint8Array, bands: number[]): { X: Float32Array; y: Uint8Array } // y = value-1; skips 0, nodata, NaN
overlayIndex(w: Window, grid: Grid, maxSide: number): { index: Int32Array; width: number; height: number; corners: [number, number][] }
  // per overlay pixel: index into w's tile, or -1; same axis-aligned Mercator grid and corner order as warpPreview
paintOverlay(index: Int32Array, labels: Uint8Array, colours: string[], rgba: Uint8ClampedArray): void // v>0 -> colours[v-1], alpha 255; else alpha 0
serializeLabels(store: LabelStore, classes: LabelClass[], grid: Grid): string
parseLabels(text: string, grid: Grid): { store: LabelStore; classes: LabelClass[] } // throws Error naming the bad field
```
**Rules.**
- **Which tool.** *Local imagery* is any raster opened with spec 001's "Open raster", except what spec 002 treats as AlphaEarth (a fetched AOI or a local AlphaEarth COG). While local imagery is active, the brush panel is shown and the polygon draw and select buttons are disabled. Earlier label polygons are neither rendered nor used, and they come back unchanged when the polygon tool returns. With no source, or with an AlphaEarth source, the polygon tool works exactly as in specs 001 and 002, and the brush panel is hidden. Spec 002's AOI tool stays available, and choosing it switches the brush to Pan. Only one source is open at a time. Opening another source discards the labels, and if they have unsaved changes the app first asks `confirm("Discard unsaved labels?")`. Cancel keeps everything.
- **Hover.** In Paint mode, a mouse or pen over the map shows `footprintRing` of the footprint under the pointer as one GeoJSON feature. It is filled with the selected class colour (fill-opacity 0.4) and outlined. Hovering never changes labels. No footprint is shown off the raster (`footprint` is null), off the globe (`isPointOnMapSurface` is false) or over the panel.
- **Strokes.** A left press (button 0) starts a paint stroke, and a right press (button 2) starts an erase stroke. Other buttons, and presses during a stroke, are ignored. Each pointer position applies `brush` to the footprint at every cell of `strokeCells(previous, current)`, so a fast drag leaves no gap. A position off the globe lifts the brush, and the stroke doesn't interpolate across the gap. The stroke ends on pointerup anywhere, pointercancel, window blur, or a move that reports no button held. Paint overwrites any class. Erase clears only the selected class. The map's `contextmenu` is prevented while local imagery is active.
- **Pan and zoom.** There are two modes, "Paint" (the default when a raster opens) and "Pan". Holding Space acts as Pan until it is released. Pan mode uses MapLibre's defaults and shows no footprint. In Paint mode, mouse and pen drags never move the map. Wheel zoom, the keyboard (arrows, `+`, `-`), the navigation control and touch gestures work unchanged. Double-click and Shift-drag don't zoom (ADR 0009).
- **Brush.** The brush is a square measured in raster pixels at every zoom, so a stroke labels the same pixels however far the map is zoomed. A screen-sized brush would label thousands of pixels per dab when zoomed out. Its size comes from `BRUSH_SIZES`. The "−"/"+" buttons and `[`/`]` step through the sizes and stop at either end, and the panel shows "Brush: 7 px". Keys `1`-`9` select the first nine classes. Shortcuts are ignored while focus is in a text field.
- **Storage.** Labels always live on the full-resolution source grid, never on the preview, and `pixelAt` maps the pointer to a source pixel. A tile is created on its first paint and deleted when its last label is erased. Painting reads no raster windows. When `brush` returns `"full"`, nothing changes and ui shows "Label limit reached (256 tiles of 256 x 256 px). Erase elsewhere first." This caps the labelled area, not the training samples, which stay uncapped (spec 001).
- **Display.** Each stored tile is drawn as its own canvas source, using `overlayIndex(w, grid, TILE_SIZE)` and `paintOverlay`, in a raster layer with nearest resampling and `raster-opacity` 0.6. It sits above the preview and below the hover layer. The index is built once per tile, so a repaint is only a lookup. A colour change repaints every overlay.
- **Classes.** The list starts as "Class 1" and "Class 2", with Class 1 selected. Colours come from a fixed 10-colour palette, in a cycle. Users can add classes up to 255 (after that Add is disabled), rename, recolour (colour input) and select. A name that is empty after trimming, or a duplicate, is refused with "Class names must be unique and not empty." and the old name stays. `model.classes` is the names in list order, so the output value is the list index (spec 001). Colours are used only by ui and the label file. `Model` is unchanged.
- **Training.** Training needs at least two classes with painted pixels. Otherwise ui shows "Paint at least two classes." Training reads only `labelWindows(store)`, each window once, applies `labelSamples` on all bands, and fits every class in the list (`fit` accepts classes with no samples). This replaces `toPixelPolygons`/`samplePixels` on this path only. If every painted pixel is nodata, ui shows "No training samples: every painted pixel is nodata."
- **Label files.** "Save labels" downloads `labels.json` containing `{ version: 1, type: "labels", width, height, epsg, gt, classes, tiles: [{ x0, y0, runs }] }`. `runs` is `[value, count, ...]` over the tile's row-major pixels, and all-zero tiles are left out. "Load labels" replaces the store and classes. If the file's grid differs from the open raster, ui shows "These labels belong to a different raster." and nothing changes. Saving or loading clears the unsaved flag. The e2e hook `__geoapp.labels` exposes `{ store, classes }`.
- **Touch and pen.** Touch never paints or shows a footprint, and touch gestures pan and zoom in both modes. A pen tip paints, the pen's barrel button (button 2) erases, and a hovering pen shows the footprint.
- **180° and MAX_LAT.** Neither needs a guard. Painting edits pixels clipped to the raster, so no geometry can cross 180° or ±MAX_LAT. `pixelAt` normalizes longitude, so every world copy hits the same pixel. Footprint rings and overlay corners use `toLonLat`, as the preview corners do, so they stay aligned with the preview across 180° on a UTM zone 60 raster. The pointer can't reach beyond ±MAX_LAT. A footprint that overhangs it still labels those pixels, and they train normally but aren't drawn.
- **Spec 001 criteria.** These still hold unchanged: 1, 3-7, 9-11, 13 and 16. Criterion 2 is superseded on local imagery by criteria 10-16 here and still holds for the polygon tool. In criterion 8, the "polygon's bounding box" part is superseded on local imagery by criterion 9 here, and its 256x256 and sink-write limits still hold. In criterion 12, the globe-rendering checks hold, and its polygon check, along with criteria 14 and 15, now applies to the polygon tool, so those tests draw with no local raster open (ADR 0009).

## Acceptance criteria
1. `pixelAt`: spec 001's reference points (`tests/fixtures/crs-points.json`, EPSG:4326, 3857, 32633) give the floor of their recorded pixel coordinates. Points within 0.01 px of a pixel edge are skipped, since several sit exactly on one. lon ± 360 gives the same pixel. On an EPSG:32660 raster that straddles 180°, lon 180.2 and -179.8 give the same pixel.
2. `footprint`: for sizes 1, 3 and 7, the window is size x size and centred on (col, row). It is clipped at raster edges, and it is null when the square misses the raster.
3. `strokeCells`: it includes both ends, consecutive cells differ by at most 1 in col and in row, and it has max(|Δcol|, |Δrow|) + 1 cells.
4. `brush`: paint overwrites another class. Erase clears only `value`, never creates a tile, and deletes a tile when its last label goes. A size-7 dab on a tile corner creates exactly 4 tiles. With `MAX_LABEL_TILES` tiles stored, a dab that needs a new tile returns `"full"` and changes nothing, while a dab inside stored tiles still applies.
5. `labelSamples`: y = value - 1, and 0, nodata and NaN pixels are skipped. A store spanning a 2x2 tile grid gives the same multiset of samples as the same labels sampled as one dense tile.
6. `overlayIndex` + `paintOverlay`: on a UTM fixture, a labelled pixel lands within 1 overlay pixel of its reference lon/lat, and the corners form a Mercator rectangle. Labelled pixels have exactly the class colour with alpha 255, and all others have alpha 0.
7. Label file: serialize then parse returns the same tiles and classes, and all-zero tiles aren't written. Parse rejects each of the following, naming the field: version not 1 or type not "labels"; width, height, epsg or gt different from the grid; a tile origin that isn't a `tileWindows` origin, or is duplicated; runs that don't sum to the window's pixel count, a count below 1, or a value above `classes.length`; an empty or duplicate class name; a colour that isn't `#rrggbb`; more than 255 classes or more than `MAX_LABEL_TILES` tiles.
8. Tool by source (e2e): with no source, polygons draw and the brush panel is hidden. After opening a local GeoTIFF, the brush panel shows, the polygon buttons are disabled, earlier polygons aren't rendered (`queryRenderedFeatures`), and a left drag adds no polygon. Once a spec 002 AlphaEarth fixture is active, the brush panel is hidden and the earlier polygons render again, unchanged.
9. Reads (instrumented 2048x2048 source): painting reads no window. Training reads exactly the stored tiles' windows, once each, each at most 256x256, and its sample count equals the labelled pixels that aren't nodata.
10. Hover (e2e): a mouse moved with no button over the raster shows one hover feature. Its ring equals `footprintRing` at `pixelAt` of the pointer within 1e-6°, and its fill is the selected colour. The store stays empty. Over the panel, or off the raster, there is no hover feature.
11. Paint and erase (e2e, on the EPSG:4326 fixture): at zoom 14 (flat Mercator), a horizontal size-7 left drag labels exactly rows r-3..r+3 from the start column to the end column, including a drag made of two moves 300 px apart. At zoom 3 (globe), a drag of a few moves labels one 8-connected set that contains the footprints at the first and last pointer pixels. A right drag over it clears the selected class and leaves another class's pixels. The `contextmenu` event has `defaultPrevented` set. Centre, zoom, bearing and pitch are unchanged afterwards.
12. Stroke end (e2e): releasing over the panel, a pointercancel, or a move with `buttons: 0` (CDP) ends the stroke, and later moves label nothing.
13. Pan and zoom (e2e): in Paint mode, the wheel changes zoom and paints nothing. With Space held, a left drag pans and paints nothing, and after Space is released a left drag paints. In Pan mode, a left drag pans, a right drag changes bearing, and nothing is painted. A double-click in Paint mode leaves zoom unchanged. A one-finger touch drag (CDP) pans in Paint mode, paints nothing and shows no footprint.
14. Pen (e2e, CDP `pointerType: "pen"`): a tip drag paints, and a barrel (right) drag erases.
15. Brush size (e2e): `]` and "+" step up through `BRUSH_SIZES` and stop at 127. `[` and "−" step down and stop at 1. The panel text follows each step ("Brush: 15 px"), and a size-15 dab labels 15x15 pixels. Typing `[`, `]` or `1` into a class name field changes neither the size nor the selected class.
16. Classes (e2e): the list starts as "Class 1" and "Class 2", with Class 1 selected. Add, rename, recolour and select (by click and by keys 1-9) all work. An empty or duplicate name shows the message and keeps the old name. Recolouring changes the overlay and the hover colour. Add is disabled at 255 classes.
17. Train (e2e, EPSG:4326 fixture): after painting two classes, `model.classes` equals the list names, and the message reports N pixels, where N is the number of labelled pixels. With only one class painted, "Paint at least two classes." appears and no model is made. Export then meets spec 001 criterion 9. With the store filled to `MAX_LABEL_TILES` through the hook, a dab on a new tile shows the limit message.
18. Label file (e2e): save, reload the page, open the same raster and load, and the store and classes equal what was saved. Loading onto another raster shows "These labels belong to a different raster." and changes nothing. Opening another raster with unsaved labels shows the confirm: Cancel keeps the raster and labels, and OK discards them.
19. Privacy (Playwright request log): painting, training, saving and loading labels make no network requests.

## Open questions for Gage
1. **Erase.** Should a right drag erase only the selected class (the default, reading "remove it" as the selected label) or every label?
2. **Save/load labels.** Are these in scope? By default they are (rule "Label files", criteria 7 and 18), because painting takes more work than drawing polygons. Deferring them drops both criteria.
3. **Brush.** The default is a square with sizes 1-127 that roughly double (default 7). Do you want a disc, or different steps?
4. **Memory cap.** The cap is 256 tiles (16 MiB), held in memory. Raise it, or store tiles in OPFS (ADR 0010 option b)?
5. **Touch.** Touch doesn't paint by default. Do you want one finger to paint and two to pan?
6. **Polygon tool with no source.** The default keeps it available, which spec 001 criteria 14 and 15 and spec 002 criterion 8 rely on. Should it appear only once an AlphaEarth source is loaded?
7. **Which files count as AlphaEarth.** The default uses whatever spec 002's reader opens as AlphaEarth. If spec 002 detects AlphaEarth COGs automatically in "Open raster", that detection decides the tool.
8. **Undo, and deleting classes.** Both are out for v1. Deleting a class would renumber labels and outputs. Do you want either now?
9. **Numbering.** Spec 002's follow-on list names 003 change detection and 004 change prediction. This spec takes 003, so those would move to 004 and 005 (002 is not edited while it is being built). ADRs 0009 and 0010 would clash if the 002 branch adds ADRs.
