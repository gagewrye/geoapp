## Scope
- `.github/workflows/ci.yml`: a `check` job, then `e2e` in 4 shards, then a `ci` summary job.
- Changes to `playwright.config.ts`, plus one npm script.
- Doc changes: the tester runs only changed e2e files, and a merge waits for green CI.

**Out of scope:** macOS or Windows runners, browser caching, merged shard reports, deploys, the @probe tests and the live HF test in CI, and fixing any test. The exceptions are criterion 11's timeouts, the frame-counted waits in criteria 12 and 13, criterion 14, and the title tags in criteria 15 and 16.
**Also out (follow-up spec 061):** selective e2e by changed area, that is, CI running only the e2e tests mapped to the `src/` paths a PR changes.

## Interfaces (no `core/` change)
- **Config** (`playwright.config.ts`):
  - `workers: 2` everywhere. `--workers` still overrides it.
  - When `process.env.CI` is set: `forbidOnly: true`, `retries: 0`, `globalTimeout: 25 * 60_000`, and `reporter: [["dot"], ["html", { open: "never" }]]`.
  - Local runs keep today's default reporter.
  - **`grepInvert` (amendment 4):**
    - On CI it matches both `@probe` and `@ci-skip`.
    - Locally it matches `@probe` only, as today, so local runs include `@ci-skip` tests.
    - Under `npm run e2e:probe` it matches nothing, as today.
    - A test is tagged by appending ` @ci-skip` to its title, as the @probe tests do.
- **Script:** `"e2e:changed": "playwright test --only-changed=main --pass-with-no-tests"`. In Playwright 1.64.1 this runs the test files that differ from `main`, plus every test file that imports a changed file. Its lifecycle name isn't `e2e:probe`, so @probe stays excluded.
- **Workflow** (`ci.yml`):
  - Triggers: `on: pull_request: branches: [main]` and `push: branches: [main]`.
  - `permissions: contents: read`.
  - `concurrency: ci-${{ github.ref }}` with `cancel-in-progress: true`.
  - **`check`:** runs on `ubuntu-latest`. It uses `actions/checkout@v6` and `actions/setup-node@v6` (`node-version: 22`, `cache: npm`), then runs `npm ci` and `npm run check`.
  - **`e2e`:** `needs: check`, with matrix `shard: [1, 2, 3, 4]`, `fail-fast: false` and `timeout-minutes: 30`. Without `fail-fast: false`, one failing shard cancels the others, so a fix loop would see only some of the failures. Letting every shard finish costs only free minutes. It does the same setup, then runs `npx playwright install --with-deps chromium` and `npx playwright test --shard=${{ matrix.shard }}/4`.
  - **On a shard failure:** `if: failure()` runs `actions/upload-artifact@v5`, which uploads `playwright-report/` and `test-results/` as `e2e-report-<shard>` with `retention-days: 14`.
  - **`ci`:** `needs: [check, e2e]` and `if: always()`. It exits 1 unless both needed jobs succeeded. This is the single required-check name.

## Acceptance criteria
1. **Triggers.** `ci.yml` triggers only on `pull_request` and `push`, each limited to `main`. It contains no `pull_request_target`, no `secrets.`, no `LIVE_HF`, and its permissions are `contents: read`. A unit test, `tests/unit/ci.test.ts`, checks this by reading the file as text.
2. **Jobs.** The same unit test checks the jobs and steps named above:
   - `e2e` needs `check`, and `ci` needs both.
   - The shard total is 4, and the matrix sets `fail-fast: false`.
   - The upload step runs only on failure.
   - The workflow has no Playwright browser cache step.
3. **Config.**
   - `npx playwright test --list` lists the tests on `main` minus criterion 14's, with no @probe test.
   - With `CI=1`, `--list --shard=k/4` for k = 1 to 4 lists every test exactly once in total (the tester compares the lists).
4. **Workers.** A plain `npx playwright test` with three or more spec files prints `using 2 workers`. Files run whole, since the config doesn't set `fullyParallel`, so a run of a single file uses 1 worker.
5. **`e2e:changed`.**
   - On a branch that changes one e2e spec file, it runs only that file.
   - If a helper in `tests/e2e/*.ts` changes, it also runs every spec file that imports the helper.
   - With no changed test files, it exits 0.
6. **The live test stays off.** In the CI report, `smart-model-live.tester.spec.ts` shows as skipped, and no @probe test runs.

12. **WASD holds count frames, not milliseconds.**

    **The helper.** One shared helper goes in `tests/e2e/helpers.ts`: `holdKeys(page, keys, { ms, frames })`, returning `{ start, samples, budget }`.
    - In the page it records the `performance.now()` of the first keydown and of the keyup.
    - It takes one sample per `requestAnimationFrame`, replacing the 25 ms interval.
    - It keeps the keys down until at least `ms` has passed since the keydown and at least `frames` map moves have been seen. A move is a sampled frame in which the start centre's screen position changed (`h.moves` in `helpers.ts`). It waits on a `waitForFunction` with a 15 s timeout. *(Wording matched to the code by amendment 4.)*
    - `budget` is the sum, over the frames between keydown and keyup, of `WASD_SPEED * min(dt, WASD_MAX_DT) / 1000`. Both constants are imported from `src/core/wasd`, as e2e already imports `src/core/pixel`. This is the distance the app's own rule allows at whatever frame rate the run gets.
    - The two local helpers it replaces, `hold` in `navigation` and `holdW` in `nav-undo.tester`, are removed.

    **The tests.**
    - **`navigation` 203 (all 3 cases):**
      - Hold W with `{ ms: 500, frames: 10 }`. `dy` must be within ±25% of `budget`, which replaces `150 ≤ dy ≤ 450`.
      - W+D uses the same hold. `down` must exceed `0.75 * budget / √2`, which replaces `> 100`.
      - The x drift, distinct-sample (at least 10), view, keyup-stop and diagonal-ratio checks are unchanged.
    - **`nav-undo.tester` 85:** `{ ms: 500, frames: 10 }`, and `dy ≥ 0.75 * budget`. *(Superseded: criterion 14 deletes this test.)*
    - **`nav-undo.tester` 44:** the lower bound becomes `dy ≥ 0.75 * budget`. The upper bound, `≤ 600 * 1.05` px/s, is unchanged.
    - **`undo-seed.tester` 30:** hold with `{ ms: 200, frames: 3 }`, then `v1.lat > v0.lat` as before. *(Superseded: criterion 14 deletes this test.)*
    - **The pre-stop waits** in `navigation` `stillWhileHeld` and the `nav-undo.tester` 70 stoppers wait for at least 3 frames instead of a fixed 150 ms.

    `nav-undo.tester` 44 and the pre-stop waits passed in this run, but they fall off the same frame-rate cliff, so they are changed preventively.

    **Verified when:** with the CPU throttled through CDP (`Emulation.setCPUThrottlingRate`, rate 6), `--repeat-each=3` of these tests passes locally. They also pass in all 4 CI shards.

**Cost.** The repo is public, so standard runners are free, with 4 vCPU and 16 GB each. One run is about 1 check job plus 4 shards, roughly 40 runner-minutes. If the repo goes private, the runners drop to 2 vCPU, and the $12 monthly allowance (about 2,000 Linux minutes) covers roughly 25 to 50 runs. Fork PRs run with a read-only token and no secrets, which CI doesn't need. Depending on the repo setting, a first-time contributor's run may wait for your approval.
