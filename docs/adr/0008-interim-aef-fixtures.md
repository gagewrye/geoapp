# 0008: Interim AEF fixtures from public data

**Status:** Accepted (orchestrator for Gage, 2026-10-26; pending Gage's review)

**Context:** ADR 0007's script reads mangrove-embed `data/chips/*/chip_NNNN.npz`, which exist only on Gage's machine (Earth Engine, his credentials), so the session building spec 002 can't make fixtures. Checked 2026-10-26 from that session: Source Cooperative AEF COGs and `aef_index.csv` answer ranged GETs with 206. ESA WorldCover v200 2021 map COGs (`https://esa-worldcover.s3.eu-central-1.amazonaws.com/v200/2021/map/ESA_WorldCover_10m_2021_v200_<tile>_Map.tif`) are reachable: 3x3° tiles, EPSG:4326, ~10 m, CC BY 4.0 (DOI 10.5281/zenodo.7254221), values 10, 20, 30, 40, 50, 60, 70, 80, 90, 95 (mangroves), 100, and 0 = no data. geotiff 3.0.5 and proj4 2.22.0 are already dependencies, and pip can install scikit-learn.

**Decision:** ADR 0007's script stays unchanged and canonical. A dev-only helper builds stand-in chips in mangrove-embed's exact format (`x` float16 [64,128,128] with invalid pixels all zero, `y` uint8 1..11 with 255 = ignore, 10 m north-up UTM, `index.csv` with `x0,y1` as upper-left) in a directory given as an argument, never committed. `scripts/fixtures/standin_chips.mjs` (Node, geotiff.js + proj4) reads 128x128 windows of the 2021 AEF COGs over the Everglades (EPSG:32617), flips bottom-up rows to north-up, and labels each pixel centre by nearest-neighbour lookup in WorldCover 2021 through proj4 (32617 -> 4326). WorldCover 10..100 map to 1..11 in listed order (mangroves 95 -> 10). WorldCover 0, pixels outside the tiles and AEF -128 give 255. Train and test chips both contain mangroves. It writes raw Int8 `x`, uint8 `y` and `index.csv`; `scripts/fixtures/pack_standin_chips.py` (numpy only) dequantizes to float16 (-128 -> all-zero vector) and writes `chip_NNNN.npz`. This split is simplest: Node already reads COGs and reprojects, numpy already writes npz and float16, and neither side hand-codes a format.

**Consequences:** No new npm or Python dependency. Committed fixtures come from stand-in chips until Gage regenerates them from his real chips. The NOTICE states which source was used; for stand-ins it credits AlphaEarth (CC BY 4.0) and "© ESA WorldCover project 2021 / Contains modified Copernicus Sentinel data (2021) processed by ESA WorldCover consortium" (CC BY 4.0) instead of the mangrove-embed v3 sources. Criterion 10's `ref.json` then compares our logreg with sklearn on WorldCover labels: it still checks the implementation, but it isn't mangrove-embed's benchmark. Classes absent from the Everglades (e.g. snow and ice) stay among the 11 `fit` classes with no samples.
