# 0016: Label overlays of one raster share one Mercator pixel grid

**Status:** Accepted (Gage, 2026-10-27, with spec 011); kept 2026-10-28 with its residual hairlines ("keep the grid as is with no gpu layer for now"); pitch rule fixed 2026-10-28 ("adr should be a rule fix"). Amends ADR 0010 ("a canvas source at tile resolution").

**Context:** ADR 0010 gives each label tile its own canvas, sampled on a Mercator grid fitted to that tile's bounding box. On grids rotated against Mercator (UTM off its central meridian) neighbouring grids are offset by fractions of a pixel, so seams get gaps and double-opacity strips (spec 011). Options: (a) one grid for the raster, pixel edges at multiples of a pitch from Mercator (0, 0), so each overlay pixel belongs to the one tile holding its centre; (b) dilate each overlay by a pixel, which closes gaps but leaves darker overlaps at `raster-opacity` 0.6; (c) one overlay for the whole raster, which breaks ADR 0010's per-tile redraw and memory bounds. The first pitch rule took the largest of the four corner tiles. That failed whenever another tile is larger in Mercator: a full middle row of an EPSG:4326 raster gave 270 px, and a row clipped at ±`MAX_LAT` about 910 px.

**Decision:** (a). Pitch = the longest Mercator bbox side, from the same densified, `MAX_LAT`-clamped bounds `overlayIndex` uses, over every tile window of the raster, / 256. It is computed once per raster open, so every overlay is at most 258 px a side, with no exceptions.

**Consequences:** No dependency. Memory per overlay stays about 256 KiB of canvas and index. Opening costs one bbox per tile (6,400 for a 20,480 px square raster). Tiles smaller in Mercator than the largest get overlays coarser than raster pixels; on a raster crossing ±`MAX_LAT`, the clipped row coarsens every tile. Hairlines remain from MapLibre rounding each source's corners independently (maplibre-gl 6.16.0 `image_source.ts`; 10 of 1008 seam samples, against 382 before). A custom WebGL layer could remove them later, under its own ADR.
